## 1. 系统概述

### 1.1 系统简介

「健康饮食积分系统」后台管理平台是面向运营管理人员提供的 Web 端和微信小程序端综合管理工具，用于管理用户、配置系统参数、审核内容、处理订单与退款、管理积分和分润等核心业务。

### 1.2 角色体系

本系统采用四级角色体系，各角色权限由高到低排列如下：

| 角色 | 标识 | 入口 | 说明 |
|------|------|------|------|
| **超级管理员** | `role=admin, is_super=true` | Web 后台 `/admin/*` | 系统最高权限，管理所有账号、配置、内容，仅能通过系统初始化脚本创建 |
| **普通管理员** | `role=admin, is_super=false` | Web 后台 `/admin/*` | 日常管理操作，无账号创建/角色变更/密码重置等高权限操作 |
| **代理商** | `role=agent` | Web 后台 `/agent/*` 或小程序 | 管理名下会员、核销积分、内容发布、拉新推广、分润查询 |
| **服务商** | `role=service_provider` | Web 后台 `/service-provider/*` 或小程序 | 管理名下客户、查看/下载报告、记录接待、网点管理 |

> ⚠️ **重要**：超级管理员只能通过系统初始化脚本 `init-web-admin.js` 创建，任何 API 接口均无法创建 admin 角色账号。

### 1.3 登录方式

#### 1.3.1 微信小程序内入口

1. 用户在微信小程序登录后，进入「个人中心」页面
2. 页面根据用户角色（`role` 字段）**动态显示**对应的管理后台入口：
   - `role=admin` → 显示「总管理后台」入口，跳转至 `/pages/admin/dashboard/dashboard`
   - `role=agent` → 显示「代理商管理」入口，跳转至 `/pages/agent/home/home`
   - `role=service_provider` → 显示「服务商管理」入口，跳转至 `/pages/service-provider/home/home`
3. 普通用户（`role=user`）不会看到任何管理入口
4. 小程序内管理功能与 Web 后台功能一致，适合移动端快速操作

#### 1.3.2 Web 端登录

**登录地址**：`/auth/web-login`

**登录方式**：账号密码方式

- **账号**：openid（如 `admin001`、`agent001`、`sp001`）或手机号
- **密码**：初始化时设定的密码（8-32位，至少包含字母和数字，支持特殊字符 `!@#$%^&*()_-+=`）

**登录流程**：

1. 打开管理后台登录页，输入账号和密码
2. 系统校验角色是否为后台账号（admin/agent/service_provider），普通用户拒绝登录
3. 校验账号状态，被封禁的账号返回 403 错误，拒绝登录
4. 校验密码（bcrypt 比对，salt rounds = 10）
5. 登录成功，生成 JWT Token（有效期 7 天），跳转至角色对应首页

**角色首页映射**：

| 角色 | 首页路径 |
|------|---------|
| 管理员 | `/admin/dashboard` |
| 代理商 | `/agent/dashboard` |
| 服务商 | `/service-provider/dashboard` |

## 2. 超级管理员（总管理后台）

> 路由前缀：`/admin`，需 `role=admin` 权限
> 超级管理员专属操作受 `superAdminOnly` 中间件保护，普通管理员无法执行

### 2.1 仪表盘

**路径**：`/admin/dashboard`

仪表盘是超级管理员登录后的首页，展示系统核心运营指标的统计概览。

**统计指标**：

| 指标 | 说明 |
|------|------|
| 总用户数 | 系统注册用户总量 |
| 打卡数 | 用户餐食打卡总次数 |
| 积分发放 | 系统累计发放的积分总量 |
| 报告数 | AI 生成的健康报告总量 |

**操作步骤**：

1. 登录后台后自动进入仪表盘页面
2. 页面顶部展示四个核心指标卡片，数据实时刷新
3. 下方展示趋势图表和最近活动记录
4. 可通过右上角时间筛选器查看指定时段的数据

---

### 2.2 账号管理

**路径**：`/admin/accounts`

管理所有后台账号（管理员/代理商/服务商），包括创建、修改角色、启用/禁用、重置密码等操作。

> ⚠️ **权限说明**：本模块下的创建账号、修改角色、启用/禁用、重置密码操作均受 `superAdminOnly` 中间件保护，仅超级管理员可执行。

#### 2.2.1 查看所有后台账号

1. 进入「账号管理」页面
2. 页面展示所有后台账号列表，包含以下信息：
   - 账号（openid）
   - 昵称
   - 角色类型（管理员/代理商/服务商）
   - 是否超级管理员
   - 手机号
   - 账号状态（正常/封禁）
   - 创建时间
3. 支持按角色筛选、按关键词搜索
4. 支持分页浏览

#### 2.2.2 创建新账号

> ⚠️ 仅超级管理员可操作（`superAdminOnly` 保护）

1. 点击页面右上角「创建账号」按钮
2. 在弹出的表单中填写以下信息：
   - **账号（openid）**：登录标识，至少 3 个字符，建议格式如 `agent001`、`sp001`
   - **昵称**：账号显示名称
   - **角色**：下拉选择，可选「代理商」或「服务商」（**admin 角色不可通过此方式创建**）
   - **手机号**：选填，11 位手机号格式
   - **密码**：选填，8-32 位，至少包含字母和数字；若不填则账号创建后无法通过 Web 登录
3. 确认信息无误后，点击「确认创建」
4. 系统校验 openid 唯一性后创建账号
5. 新账号可使用 openid + 密码通过 `/auth/web-login` 登录

> ⚠️ **重要**：超级管理员账号只能通过系统初始化脚本创建，无法通过后台界面创建 admin 角色账号。

#### 2.2.3 修改账号角色

> ⚠️ 仅超级管理员可操作（`superAdminOnly` 保护），需二次确认

1. 在账号列表中，找到目标账号
2. 点击操作列的「修改角色」按钮
3. 在弹出的对话框中选择新角色（仅可选 agent 或 service_provider）
4. 系统弹出二次确认对话框，显示变更前后的角色信息
5. 确认变更后，系统更新角色
6. **限制**：
   - admin 角色不可变更
   - 超级管理员不可被降级
   - 被封禁的账号可修改角色但需先解封才能使用

#### 2.2.4 启用/禁用账号

> ⚠️ 仅超级管理员可操作（`superAdminOnly` 保护）

1. 在账号列表中，找到目标账号
2. 点击操作列的「启用」或「封禁」按钮
3. 封禁后该账号立即无法登录：
   - Web 后台登录接口返回 403 错误
   - 微信小程序登录接口返回 403 错误
   - 已有的 JWT Token 在过期前可能仍被使用（建议同时通知用户下线）
4. 启用后恢复登录权限
5. **限制**：超级管理员不可被封禁

#### 2.2.5 重置账号密码

> ⚠️ 仅超级管理员可操作（`superAdminOnly` 保护），需二次确认

1. 在账号列表中，找到目标账号
2. 点击操作列的「重置密码」按钮
3. 在弹出的对话框中输入新密码（8-32 位，至少包含字母和数字）
4. 系统弹出二次确认对话框
5. 确认后密码重置生效，原密码失效
6. **限制**：超级管理员自身的密码不通过此接口重置，只能通过初始化脚本重置

### 2.3 用户管理

**路径**：`/admin/users`

#### 2.3.1 用户列表

1. 进入「用户管理」页面
2. 页面展示所有注册用户列表，包含：头像、昵称、openid、手机号、角色、会员状态、注册时间等
3. **搜索功能**：支持按昵称、openid、手机号关键词搜索
4. **筛选功能**：
   - 按角色筛选（普通用户/会员）
   - 按状态筛选（正常/封禁）
   - 按注册时间范围筛选
5. 支持分页浏览，默认每页 20 条

#### 2.3.2 用户详情查看

1. 在用户列表中，点击目标用户的「查看详情」
2. 进入用户详情页，展示：
   - 基本信息（昵称、头像、openid、手机号、角色、会员状态）
   - 积分信息（当前积分、累计获得、累计消耗）
   - 打卡记录统计
   - 健康报告列表
   - 订单记录
   - 活跃度数据

#### 2.3.3 修改用户状态（封禁/解封）

1. 在用户列表或详情页中，点击「封禁」或「解封」按钮
2. 封禁用户后，该用户无法登录小程序
3. 解封后恢复正常使用

#### 2.3.4 修改用户角色

1. 在用户列表或详情页中，点击「修改角色」
2. 可调整用户的角色标签（如从普通用户转为会员，或从会员转为普通用户）
3. 确认变更后生效

### 2.4 系统配置

**路径**：`/admin/config`

管理全局业务参数，所有配置修改**实时生效**，缓存自动失效。

#### 2.4.1 配置项列表

配置项按分类组织，支持分类筛选：

| 分类 | 配置项 Key | 说明 | 默认值 |
|------|-----------|------|--------|
| **sign_in（签到）** | `sign_in.base_points` | 签到基础积分 | `5` |
| | `sign_in.milestones` | 连续签到里程碑奖励（天数:积分） | `{"7":10, "30":30, "100":100}` |
| **clock_in（打卡）** | `clock_in.daily_limit` | 每日打卡积分上限次数 | `3` |
| | `clock_in.points_icon` | 图标打卡积分 | `10` |
| | `clock_in.points_image` | 图片打卡积分 | `10` |
| | `clock_in.points_follow_plan` | 遵循计划打卡积分 | `20` |
| **course（课程）** | `course.points` | 课程完成积分 | `10` |
| | `course.progress_threshold` | 课程完成进度阈值（%） | `80` |
| **invite（邀请）** | `invite.points_register` | 被邀请人注册奖励积分 | `50` |
| | `invite.points_active` | 被邀请人活跃奖励积分 | `100` |
| | `invite.points_milestone` | 邀请里程碑奖励积分 | `200` |
| | `invite.milestone_count` | 邀请里程碑人数 | `2` |
| **assessment（测评）** | `assessment.monthly_limit` | 每月测评次数上限 | `1` |

#### 2.4.2 修改配置值

1. 在配置列表中找到目标配置项
2. 点击「编辑」按钮
3. 在弹出的编辑框中修改配置值
4. 点击「保存」
5. **修改后即时生效**，系统自动清除相关缓存，60 秒内所有节点生效
6. 配置修改记录可在操作日志中查看

#### 2.4.3 重置为默认值

1. 在配置列表中找到目标配置项
2. 点击「重置为默认值」按钮
3. 系统弹出确认对话框
4. 确认后，配置值恢复为系统预设默认值，缓存自动刷新

### 2.5 违禁词库

**路径**：`/admin/forbidden-words`

管理 AI 报告生成时的违禁词检测库，确保报告内容符合医疗合规要求。

#### 2.5.1 违禁词列表

1. 进入「违禁词库」页面
2. 页面展示所有违禁词条目，包含：关键词/正则、分类、状态、创建时间
3. **按分类筛选**：
   - 诊断类（如"确诊"、"诊断为"）
   - 治疗类（如"治疗"、"用药"）
   - 效果承诺类（如"保证治愈"、"根治"）
   - 恐吓类（如"不治将危及生命"）
   - 其他
4. 支持按关键词搜索、按状态筛选（启用/禁用）

#### 2.5.2 新增违禁词

1. 点击「新增违禁词」按钮
2. 填写信息：
   - **关键词/正则表达式**：输入匹配模式（支持正则表达式）
   - **分类**：选择所属分类
   - **说明**：选填，描述该违禁词的匹配规则和用途
3. 系统自动进行 **ReDoS 防护检测**：
   - 检测正则表达式是否存在灾难性回溯风险
   - 检测通过后才可保存
   - 若检测到风险，系统提示修改正则表达式
4. 确认保存

#### 2.5.3 编辑违禁词

1. 在违禁词列表中，点击目标条目的「编辑」按钮
2. 修改关键词/正则、分类、说明等信息
3. 修改正则表达式时同样会进行 ReDoS 防护检测
4. 保存修改

#### 2.5.4 删除违禁词

1. 在违禁词列表中，点击目标条目的「删除」按钮
2. 系统弹出确认对话框
3. 确认后删除，删除后该违禁词不再参与检测

### 2.6 报告管理

**路径**：`/admin/reports`

管理 AI 生成的健康报告，进行复核审核。

#### 2.6.1 待复核报告列表

1. 进入「报告管理」页面
2. 默认展示待复核（flagged）的报告列表
3. 支持按状态筛选：待复核、已通过、已拒绝
4. 支持按用户搜索
5. 列表展示：报告 ID、用户信息、生成时间、状态、标记原因

#### 2.6.2 报告审核

1. 在待复核列表中，点击目标报告进入详情页
2. 查看报告完整内容和被标记的违禁词/问题
3. 执行审核操作：
   - **通过**：报告标记为已审核，正常展示给用户
   - **拒绝**：报告标记为被拒绝，不展示给用户，需填写拒绝原因
   - **重写**：重新调用 AI 生成报告内容（使用当前激活的 Prompt 版本），原报告保留为历史版本

#### 2.6.3 报告反馈统计

1. 在报告管理页面，切换到「反馈统计」标签
2. 展示用户对报告的反馈数据：
   - 满意/不满意比例
   - 常见反馈原因分布
   - 按时间段统计趋势

### 2.7 Prompt 版本管理

**路径**：`/admin/prompts`

管理 AI 生成健康报告使用的 Prompt 版本，支持版本切换和回滚。

#### 2.7.1 Prompt 列表

1. 进入「Prompt 管理」页面
2. 展示所有 Prompt 版本列表，包含：
   - 版本号
   - 版本描述
   - 创建时间
   - 是否为当前激活版本
3. 当前激活版本以高亮标识显示

#### 2.7.2 创建新 Prompt 版本

1. 点击「创建新版本」按钮
2. 填写信息：
   - **版本描述**：简要说明该版本的变化
   - **Prompt 内容**：完整的 Prompt 文本
3. 保存后生成新的 Prompt 版本，默认为未激活状态

#### 2.7.3 激活指定版本

1. 在 Prompt 列表中，找到要激活的目标版本
2. 点击「激活」按钮
3. 系统弹出确认对话框，提示切换后新报告将使用此版本生成
4. 确认后：
   - 原激活版本自动变为未激活
   - 目标版本变为激活状态
   - 后续新生成的报告使用新激活的 Prompt 版本
5. 已生成的旧报告不受影响

### 2.8 内容发布审核

**路径**：`/admin/posts`

审核代理商发布的图文信息内容，确保合规后再公开展示。

#### 2.8.1 代理商发布内容列表

1. 进入「内容发布审核」页面
2. 展示代理商提交的图文信息列表：
   - 标题、摘要
   - 发布者（代理商信息）
   - 提交时间
   - 审核状态（待审核/已通过/已拒绝）
3. 支持按审核状态筛选、按发布者筛选

#### 2.8.2 审核通过/拒绝

1. 在待审核列表中，点击目标内容进入审核页
2. 查看图文详情（标题、正文、配图）
3. 执行审核操作：
   - **审核通过**：内容正式发布，名下会员可见
   - **审核拒绝**：需填写拒绝原因，内容不发布，代理商可查看拒绝原因后修改重新提交

### 2.9 资讯管理

**路径**：`/admin/articles`

管理系统发布的健康资讯文章。

#### 2.9.1 资讯列表

1. 进入「资讯管理」页面
2. 展示所有资讯文章列表：标题、分类、状态（草稿/已发布/已下架）、发布时间、阅读量
3. 支持按状态筛选、按分类筛选、按关键词搜索

1. 点击「创建资讯」按钮
2. 填写信息：
   - **标题**：资讯标题
   - **分类**：选择资讯分类
   - **正文**：富文本编辑器编写内容

   - **状态**：选择保存为草稿或直接发布

#### 2.9.3 编辑资讯

1. 在资讯列表中，点击「编辑」按钮

#### 2.9.5 删除资讯

1. 点击「删除」按钮
2. 系统弹出确认对话框
3. 确认后永久删除，**不可恢复**

### 2.10 礼品管理

**路径**：`/admin/gifts`

**路径**：`/agent/write-off`

用于会员到店消费时，线下核销扣减积分。

1. 进入「积分核销」页面
2. 输入以下信息：
   - **用户 ID**：输入或扫码获取目标会员的用户 ID
   - **核销积分**：本次核销扣减的积分数量
   - **核销原因**：选填，说明核销用途（如"到店消费-套餐A"）

> ⚠️ **幂等防护**：系统自动为每次核销生成幂等键，网络波动或重复点击不会导致重复扣减积分。如核销后页面未响应，请先查看核销记录确认是否已成功，避免重复操作。

## 5. 系统初始化

### 5.1 初始化流程

首次部署系统时，需按以下顺序执行初始化脚本：

```
部署服务器
  → 配置 .env（数据库连接、JWT 密钥、时区等）
  → node scripts/init-db.js（初始化数据库表结构）
  → node scripts/init-web-admin.js（创建超级管理员账号）
  → node scripts/seed-gifts.js（插入礼品种子数据）
  → 启动服务（npm start）
  → 超级管理员登录 Web 后台进行后续配置
```

### 5.2 环境准备

### 5.4 init-web-admin.js — 超级管理员创建

**脚本路径**：`scripts/init-web-admin.js`

**用途**：创建超级管理员账号，这是创建 admin 角色账号的唯一方式。

**执行方式一：命令行参数**

```bash
node scripts/init-web-admin.js \
  --openid=admin001 \
  --nickName=超级管理员 \
  --phone=13800000000 \
  --password=YourStr0ngP@ss
```

**执行方式二：交互式输入**

```bash
node scripts/init-web-admin.js
# 按提示依次输入：账号(openid)、昵称、手机号、密码
```

**密码规则**：8-32 位，至少包含字母和数字，支持特殊字符 `!@#$%^&*()_-+=`

**执行逻辑**：

1. 检查指定 openid 是否已存在
2. 若不存在，创建新账号并设置 `is_super=true`
3. 若已存在但无密码，补充设置密码
4. 若已存在且有密码，提示账号已存在，不覆盖
5. 密码使用 bcrypt 加密存储（salt rounds = 10）

> ⚠️ **重要**：超级管理员密码务必妥善保管。忘记密码后只能通过此脚本重置（需先清除旧密码记录），API 接口无法修改超级管理员密码。

### 5.6 迁移脚本说明

以下迁移脚本用于从旧版本升级时的数据库结构调整：

| 脚本 | 用途 | 执行时机 |
|------|------|---------|
| `scripts/migrate-add-is-super.js` | 添加 `is_super` 字段到用户表，区分超级管理员 | 从无 is_super 字段的旧版本升级时 |
| `scripts/migrate-add-password.js` | 添加 `password` 字段到用户表，支持 Web 登录 | 从无密码字段的旧版本升级时 |
| `scripts/migrate-fix-column-types.js` | 修复列类型（如 VARCHAR 长度调整、INT 类型修正） | 从字段类型不规范的旧版本升级时 |
| `scripts/migrate-sync-columns.js` | 同步新增列（新增业务字段） | 新版本添加新字段时 |

**迁移脚本执行顺序**（从旧版本升级时）：

```bash
# 按版本依赖顺序执行
node scripts/migrate-add-password.js       # 1. 添加密码字段
node scripts/migrate-fix-column-types.js    # 2. 修复列类型
node scripts/migrate-sync-columns.js        # 3. 同步新列
node scripts/migrate-add-is-super.js        # 4. 添加 is_super 字段
```

> ⚠️ **建议**：执行迁移脚本前，先备份数据库。迁移脚本通常不可逆，执行后无法自动回滚。
